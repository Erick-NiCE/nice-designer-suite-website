The Suite

4 product tools

The high-level tools that make up NiCE Designer. Each one is available in the Figma plugin, Chrome extension, or both — and some unlock additional capabilities when connected via Supercharge. Parity's cross-client comparison is now a feature inside Frontend Audit rather than its own tool. Convert has been dropped entirely — for SOL → Lyra conversion work, use Claude Design alongside the official Lyra design system reference instead.

MCP Server

55 MCP tools

Called directly by Claude when Supercharge is connected. All tools accept target: "figma" | "chrome" | "auto". Start the server with cd packages/mcp-server && node src/index.js (default port 7331).

Connect & diagnose Confirm Claude can actually see Figma and Chrome before anything else runs.
list_targetsFigma + Chrome

Lists which clients — Figma, Chrome, or both — are live on the MCP hub right now.

Why: Stops you from waiting on a tool that was never going to reach anything. Always the cheapest first call.

get_diagnosticsFigma + Chrome

Full health report on the bridge: this process, the hub, connected sessions, recent drop-outs, and a plain-English next step.

Why: Turns "it just does not work" into a specific thing to click. Run it the moment a tool says nothing is connected.

check_librariesFigma only

Verifies the SOL or Lyra library is actually linked to the open Figma file.

Why: A missing library silently makes every conversion fall back to bundled values. This catches that before you convert anything.

Choose what to work on Set the scope — a whole page, one artboard, or a single inspected element.
get_selection_infoFigma + Chrome

Reports the selected Figma layer or the inspected Chrome element, so scope is explicit rather than assumed.

Why: Guarantees the audit or fix lands on the thing you meant. No silent whole-page conversions when you wanted one button.

select_pageChrome only

Clears the inspected element so audits and fixes cover the entire page again.

Why: One call to zoom back out after drilling into a component.

start_inspectChrome only

Turns on the extension's inspect mode so the next element you click becomes the scope.

Why: Point at the thing you care about instead of describing it in words.

stop_inspectChrome only

Leaves inspect mode without changing the current selection.

Why: Gets the picking cursor out of your way so you can use the page normally.

focus_nodeFigma only

Scrolls to and selects a specific node id on the Figma canvas.

Why: Every audit row becomes clickable — go straight from "issue #14" to the actual layer.

screenshot_pageFigma + Chrome

Captures the current page or artboard as an image Claude can look at directly.

Why: Lets Claude judge things a token audit cannot see — visual hierarchy, crowding, whether it simply looks wrong.

Score & measure Read your current state. The audits return a gauge plus the issue list behind it.
run_full_auditFigma + Chrome

Audits colors, typography, spacing, radius, components and accessibility in one pass and returns an overall 0–100 score with per-domain issue counts.

Why: One number you can put in front of a stakeholder, plus the exact list of what is dragging it down.

lyra_compliance_reportFigma + Chrome

A full audit plus the accessibility pass, pinned to Lyra, formatted as a report rather than a raw issue dump.

Why: The artifact to paste into a design review or a ticket — score, gauge, and the top offenders, already prose.

audit_colorsFigma + Chrome

Classifies every fill and stroke as on-token, bound to the wrong design system, or a raw value with no binding.

Why: Tells you not just how many colors are off but how many are one click from being right — so you know whether this is ten minutes of work or a week.

audit_text_stylesFigma + Chrome

Matches every text node on family, size and weight together, and names the role-equivalent token it should be using.

Why: Catches the sneaky case — right size, wrong family — that eyeballing a design never finds.

audit_spacingFigma + Chrome

Finds padding, gap and margin values that are off-scale, or on-scale but not bound to a variable.

Why: Surfaces the "looks fine, breaks on theme change" class of problem, which is most of what fails in handoff.

audit_radiusFigma + Chrome

Finds corner radii that are off-scale or unbound, reading the real per-corner binding slots.

Why: Radius drift is the fastest way a page stops looking like the system. This is the cheapest audit to act on.

audit_componentsFigma only

Finds instances from the wrong library or from no library, and names a 1:1 replacement where one exists.

Why: Detached and off-system components are what make a file un-maintainable. This is the list to fix first.

audit_accessibilityFigma + Chrome

WCAG-oriented scan: contrast, tap targets, small text, ARIA, alt text, labels, focus outlines, heading order, landmarks.

Why: Errors and warnings split out separately, so you can see what is a genuine blocker versus what is polish.

scan_variablesFigma + Chrome

Enumerates every variable currently bound in the scope, and every property that should be bound but is not.

Why: The raw data behind the spacing and radius scores, if you want to reason about bindings yourself.

get_audit_filtersFigma + Chrome

Returns the user's active audit filters — which issue classes are currently excluded from the score.

Why: Keeps the score honest. A 96 with contrast checks switched off is not a 96, and this is how you find out.

set_audit_filtersFigma + Chrome

Turns individual issue classes in or out of scope for the score.

Why: Lets you park issues that are genuinely out of scope for this project without them nagging in every audit.

Fix everything at once Whole-page and whole-frame conversions. Dry-run by default, and they report the score they moved.
convert_page_to_lyraChrome only

Runs every applicable fixer across a live page and returns a before/after score delta.

Why: The single biggest jump in score you can get in one call — and you see exactly how many points it bought.

migrate_to_lyraFigma only

The Figma equivalent: applies the selected fixer families across a frame and reports the score delta.

Why: Migrates a whole artboard without hand-picking rows, with a before/after gauge to show your team.

convert_colorsFigma + Chrome

Binds the chosen color tokens to the listed fills and strokes.

Why: Reports how many of the original color issues it actually resolved, so a partial fix never gets reported as a win.

convert_text_stylesFigma + Chrome

Applies the matching type token to the given text nodes, or to every eligible one.

Why: Type is the most visible domain — this is the change people notice, and it comes with a resolved-count.

fix_spacingFigma + Chrome

Binds spacing variables to off-scale or unbound padding, gap and margin values.

Why: Usually the highest-yield, lowest-risk fix in the set — values barely move, but the score does.

fix_radiusFigma + Chrome

Binds radius variables to off-scale or unbound corner radii.

Why: Small visual change, large consistency gain, and it takes one call.

fix_accessibilityFigma + Chrome

Applies the automated remediation for a specific accessibility issue type on a node.

Why: Clears the mechanical a11y failures — labels, alt text, tap targets — so human attention goes to the judgement calls.

convert_componentFigma only

Replaces one instance with the equivalent component from the target design system.

Why: Gets you a real library instance — inheriting future updates — instead of a look-alike that drifts.

convert_modeFigma + Chrome

Re-binds the scope to the light or dark tokens of the given system.

Why: Produces a genuine dark variant built from tokens, not an inverted screenshot.

generate_multi_systemFigma only

Copies the selection and converts the copy to the other design system, leaving the original untouched.

Why: Side-by-side SOL and Lyra versions for a migration pitch, with zero risk to the original.

Fix one thing at a time Surgical, per-property edits with a clean one-click revert for each.
apply_single_colorFigma + Chrome

Applies one color token — or a raw hex via customHex — to a single fill or stroke.

Why: Try a value in one call and undo it in one call. This is the lane for "just make this blue".

apply_single_textFigma + Chrome

Applies one type token — or a raw size via customFontSize — to a single text node.

Why: Iterate on one heading without touching the other forty.

apply_single_spacingFigma + Chrome

Applies one spacing token — or a raw number via customValue — to a single property.

Why: Nudge one gap by hand when the token scale genuinely does not have the right step.

apply_single_radiusFigma + Chrome

Applies one radius token — or a raw number via customValue — to a single corner or all four.

Why: Fix the one card whose corners are wrong, without a page-wide pass.

revert_single_colorFigma + Chrome

Restores the snapshot captured when that exact fill or stroke was changed.

Why: Per-row undo that survives other edits — no losing four good changes to walk back a fifth.

revert_single_textFigma + Chrome

Restores the snapshot captured when that text node was changed.

Why: Try a type token, dislike it, put it back exactly as it was.

revert_single_spacingFigma + Chrome

Restores the snapshot captured when that spacing property was changed.

Why: Reverses a single nudge without disturbing the rest of the layout.

revert_single_radiusFigma + Chrome

Restores the snapshot captured when that radius was changed.

Why: Reverses a single radius edit cleanly.

Undo & history Step back out of any bulk change without leaving the conversation.
undo_last_conversionFigma + Chrome

Rolls back the most recent bulk conversion in one call.

Why: Lets you run a big conversion to see what it does, knowing the exit is one sentence away.

get_conversion_historyFigma + Chrome

Returns the ordered history of applied changes with the current position in it.

Why: A written record of what this session actually touched — useful for a changelog or a handoff note.

revert_to_history_indexFigma + Chrome

Steps the design back to a chosen entry in the history.

Why: Explore aggressively, then land on whichever version was best — not just the last one.

Restyle the live page Chrome only. Inject CSS, flip dark mode, and switch on accessibility overlays.
apply_css_overridesChrome only

Injects selector-scoped CSS declarations into the live page.

Why: Restyle anything on a page you do not own, and see the result immediately. Pass clear:true so re-runs replace rather than stack.

clear_css_overridesChrome only

Strips every override this session injected, returning the page to its shipped styling.

Why: A clean baseline in one call, so an experiment never contaminates the next audit.

polish_pageChrome only

Toggles dark-mode simulation, token-styled scrollbars, and positional hover overlays.

Why: Dark mode without a build, on any page — the fastest way to find out what breaks.

a11y_overlayChrome only

Toggles small-tap-target highlighting, non-token color flagging, and colorblind simulation.

Why: Makes accessibility problems visible on screen, which is far more persuasive in a review than a list of counts.

Spec Mode Turn a design into CSS, tokens, and specs a developer can paste in.
extract_dev_detailsFigma + Chrome

Size, fills, strokes, typography, auto-layout and CSS for the current selection.

Why: The handoff spec a developer asks for, without a screenshot-and-annotate round trip.

extract_all_cssFigma + Chrome

Emits a CSS document covering every node in scope.

Why: A real starting point for implementation rather than a pile of values to retype.

extract_token_cssFigma + Chrome

Emits the design system's tokens as CSS custom properties.

Why: Drop it into a stylesheet and the rest of the exported CSS resolves against real tokens.

export_design_tokensFigma + Chrome

Returns the color, type, spacing and radius palettes for SOL or Lyra in either mode.

Why: Lets Claude propose real token names instead of guessing at them from memory.

sync_storybook_componentsFigma + Chrome

Pulls the live component inventory from a Storybook instance into the plugin.

Why: Component audits start matching what engineering actually shipped, not last quarter's library.

get_storybook_sync_statusFigma + Chrome

Reports when the last sync ran and how many components it brought in.

Why: Tells you whether a component audit is trustworthy or built on stale data.

Decide & review Judgement calls — is this good enough to move to the next step?
run_ux_evalFigma + Chrome

Assembles a live audit, the design and ticket links, and the 10-question prioritisation framework — then hands the judgement to Claude.

Why: The answer to "is this ready for dev?" argued on reach, real pain and opportunity cost — not just on whether the tokens are clean.

Keep the server current Check whether a newer MCP server build is available, and pull it in.
check_for_updatesFigma + Chrome

Fetches origin and reports whether the local MCP server checkout is behind, with the commit list and version numbers.

Why: Know there is an update before running it, instead of finding out a feature is missing after the fact.

install_updateFigma + Chrome

Fast-forwards the local checkout to origin and runs npm install for whatever changed. Only works from a git checkout, and only when the working tree is clean.

Why: Gets new tools and fixes onto disk in one call — though the running process still needs a restart to actually load them, which the response always states.

Escape hatch Raw access for anything the tools above do not cover yet.
call_pluginFigma + Chrome

Forwards any raw UIMessage straight to the plugin, bypassing the typed tools.

Why: Reaches plugin capability that has no tool yet. Powerful, unvalidated — use it when nothing else fits.

Claude Skills

11 skills

Skills are context files (SKILL.md) that give Claude a playbook for a specific workflow. Load a skill by saying "load the [skill-name] skill" in Claude chat — then Claude uses the right MCP tools in the right sequence. All skills require Supercharge.

Score & triage Turn a pile of issues into a ranked list of what to do first.
a11y-triage
Figma + Chrome

Ranks accessibility issues by severity × reach and returns a top-N action list. Converts an unreadable issue dump into three things to fix this afternoon.

Answers: "I have hundreds of a11y issues — where do I actually start?"

manual-fixes-checklist
Figma + Chrome

Audits, dry-runs every fixer, then reports only what survives — grouped and prioritised. An honest to-do list for the last mile to 100%, so nobody promises a score the tools cannot reach.

Answers: "What is left for a human after the auto-fixers have run?"

Convert to Lyra Set expectations and scope before anything gets rewritten.
lyra-visual-patterns
Figma + Chrome

Reference for Lyra page chrome, surfaces, tables, panels, nav, chips and AI affordances in light and dark. Load it before any conversion and you know what you are going to get — no surprise redesigns.

Answers: "What is a correctly-converted Lyra page supposed to look like?"

Spec Mode Produce the spec or the CSS a developer can build from.
figma-element-css
Figma only

Turns the selected Figma node into production CSS with Lyra tokens substituted where they match. Output that survives a theme change, instead of hard-coded hex and px.

Answers: "What is the CSS for this layer?"

browser-element-specs
Chrome only

Pulls computed CSS for the inspected element and annotates every raw value with its nearest token. A spec a developer can act on, not just a description of what is there.

Answers: "What are the design specs of this element on the page?"

Design ↔ build parity Compare what was designed against what actually shipped.
figma-chrome-parity
Both required

Aligns Figma layers to page elements by name and diffs colors, type, spacing, radius and shadows. Ends the "it looks off but I cannot say why" review with a per-property drift table.

Answers: "Does the live site actually match the Figma?"

artboard-to-page
Both required

Maps artboard styling onto page selectors and applies it as CSS overrides after you confirm the mapping. Demo a redesign on the real product in minutes, with no branch and no build.

Answers: "Can we make this real page look like this artboard?"

Live-page QA Catch what only breaks in the real browser.
dark-mode-parity
Chrome only

Audits colors in light, simulates dark, audits again, and always restores the baseline. Only the delta — what breaks in dark and what breaks in light. No re-reading the full audit.

Answers: "Does this page work in dark mode, or only in light?"

Design-system maintenance Feed what you learn back into the system itself.
token-candidates
Figma + Chrome

Groups recurring raw values across all four domains and ranks the ones worth promoting. Fixes the cause once upstream instead of the same symptom on thirty screens.

Answers: "Which of these custom values should just become Lyra tokens?"

Decide & review Pass, fail, or not-yet — with the reasoning written down.
ux-eval
Figma + Chrome

Answers all ten prioritisation questions against real evidence, then states pass / pass-with-conditions / not-yet. A defensible verdict with the reasoning attached — the thing you can actually take to a VP.

Answers: "Is this good enough to move to the next step, or to dev?" — by Bill Bangs

NICE product knowledge Real context on NICE and its products, so design work is grounded instead of generic.
nice-product-knowledge
Figma + Chrome

Sourced reference on NICE the company and its product lines (CXone Mpower, Enlighten AI, Actimize, Evidencentral) — compiled from public material with citations. Design decisions grounded in what the real product and its real users are, instead of generic SaaS assumptions.

Answers: "What does this NICE product actually do, and who uses it?"
