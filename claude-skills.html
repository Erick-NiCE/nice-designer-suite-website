What is a skill?

Skills make Claude an expert tool operator

NiCE Designer ships 12 Claude skills. A skill is a context file (SKILL.md) that tells Claude exactly how to use the MCP tools for a specific job. You run a skill just by naming it - "run the [skill-name] skill", or even just "run North Star Fox" - Claude looks it up with list_skills and loads it with get_skill automatically, then uses the right MCP tools in the right order.

Each skill pre-loads Claude with the correct tool sequence, common pitfalls, expected outputs, and quality checks for a particular workflow. Without a skill, Claude knows the tools exist but has to figure out the right approach on its own. With a skill loaded, it already has a playbook.

Skills are stored in the skills/ directory of the plugin, and published here so every connected Claude session gets the latest content with no reinstall. Each skill has a SKILL.md file; the same set is bundled into the packaged Chrome build at builds/chrome/skills/ as an offline fallback. ux-eval and north-star-fox are grouped as Decide & review; nice-product-knowledge as NICE product knowledge - see the groups below.

MCP server

57 tools, 12 groups

NiCE Designer exposes 57 MCP tools via the local WebSocket server at 127.0.0.1:7331. Most accept target: "figma" | "chrome" | "auto" (the skill-lookup tools are the exception - pure introspection, no target needed), organized into 12 groups - connect & diagnose, run a skill, scope, score & measure, bulk fixes, one-at-a-time fixes, undo & history, live-page restyling, Spec Mode, decide & review, keeping the server current, and an escape hatch for anything the typed tools don't cover yet.

The full reference - every tool, its group, target client(s), and what it does - lives on the Tools page, generated straight from the MCP server's own catalog so it never drifts out of sync.

Tips

Before you run a skill

A few things to know that will save you time and prevent silent failures.

🔌
Always call list_targets first. Check which clients are connected before running any skill. Targeting Figma when only Chrome is connected does nothing and returns no error.
👥
Two clients required for: artboard-to-page and figma-chrome-parity. Both the Figma plugin and Chrome extension must be active and connected before running these skills.
🌐
Chrome-only skill: dark-mode-parity only works against a live page. There is no Figma equivalent. Run it with the Chrome extension active.
🏭
Figma-only skill: figma-element-css requires a node selected inside Figma. It cannot be run against Chrome page elements.
✨
Always load lyra-visual-patterns before any Lyra conversion. This sets Claude's expectations for token naming and visual patterns. Skipping it leads to inconsistent migration results.
🔒
Audit tools are safe anytime. All audit and introspection tools are read-only - they never modify your design. Run them freely. Conversion tools modify the design and support undo via undo_last_conversion.
