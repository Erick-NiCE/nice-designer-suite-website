Troubleshooting

Fixes for the most common install and connection problems. Find your symptom below.

Chrome extension not loading
Make sure Developer mode is on. Paste chrome://extensions (Chrome) or edge://extensions (Edge) into the address bar - the switch is at the top-right in Chrome and at the bottom of the left sidebar in Edge. Then check that you picked the NiCE Designer Chrome folder itself - the one containing manifest.json - not the folder above it or the zip. If it still won't load, remove the extension and use Load unpacked again.
Claude connector tools are missing
The connector only loads on a completely fresh start of Claude Desktop. Force quit it (on Mac: right-click the Claude icon in the Dock, hold Option, choose Force Quit), then reopen it. Closing the window or pressing Cmd + Q often leaves it running in the background. Also check Settings > Extensions in Claude Desktop shows nice-designer-mcp under Installed on your computer.
Supercharge won't turn on, or shows no address
The Claude Desktop connector starts the server, so Claude Desktop has to be running. After it starts, the Supercharge panel should show a green dot and ws://127.0.0.1:7331. If not, check that port 7331 isn't used by another process. If you run the server by hand, NICE_MCP_WS_PORT=7332 node src/index.js uses a different port. If you set up the manual config, make sure the path in claude_desktop_config.json is absolute, not relative.
Claude can't see any targets
At least one client - the Chrome extension or the Figma plugin - must be open and connected to the MCP server. Ask Claude to call list_targets first - it tells you exactly which clients are registered. If the list is empty, check the connection in each client.
The extension lost my settings after an update
Chrome ties the extension's storage to the folder path you loaded. Update by dragging the new files into your existing folder and clicking Reload on chrome://extensions, rather than loading a new folder. See the Update Guide.
Figma plugin won't open
Make sure you installed it from the Figma Community, not a local unpacked version. Check that the plugin isn't in your organization's blocked plugin list - contact your Figma admin if unsure. On a view-only seat plugins can't run at all; use the no-plugin route.
Save Local Copy is greyed out in Figma
Figma lets a file owner, or an Enterprise admin, switch off exporting for view-only users. Per file, it's the Viewers can copy, share, and export from this file checkbox under Advanced in the file's Share settings. Org wide, an admin controls it under Admin > Settings > External access > File exporting. A per-file restriction still applies even when the org setting is permissive, so check both.

Still stuck? Re-run the checks in the install guide, or browse the FAQ.
