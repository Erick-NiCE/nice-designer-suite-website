FAQ

Common questions

Answers on how NiCE Designer works, what it does and doesn't do, and how to get set up.

How do the NiCE Designer tools understand the design system?

The tools are built on three sources of truth:

  • Storybook - the design team's live component library at na1.dev.nice-incontact.com/sol, which provides live component definitions, variants, and usage examples.
  • Figma foundation files - the Lyra and SOL Foundation Figma files, which define the canonical token sets, spacing scales, color palettes, and typography styles for both systems.
  • Claude design system knowledge - AI context built from the same sources, enabling Claude to reason about tokens, patterns, and compliance in natural language.
Does NiCE Designer generate designs or pages?

No. NiCE Designer works with pages and designs that already exist - it audits, converts, and annotates them rather than generating new ones from scratch.

The philosophy: generation is best left to tools like Claude Code for code and to UX designers for design. NiCE Designer's job is to ensure that what's already been built actually matches the design system.

What is Supercharge?

Supercharge is what happens when NiCE Designer connects to Claude via the local MCP server. On their own, the Figma plugin and Chrome extension can audit and convert designs. With Supercharge connected, Claude can drive both tools simultaneously using natural language - running multi-step workflows, reasoning across Figma and the live page at the same time, and using the full library of MCP tools and Claude skills.

Think of the plugin and extension as the hands, and Supercharge as the brain.

What's the difference between SOL and Lyra, and can NiCE Designer convert between them?

SOL and Lyra are NiCE's two design systems, each with their own token sets, spacing scales, and component libraries. NiCE Designer's convert_design_system skill maps a frame from one system to the other, using semantic role (text, background, border, icon) so tokens that differ by role are handled correctly rather than mapped one-to-one by name.

Do I need the MCP server running to use the Figma plugin or Chrome extension?

No. The Figma plugin and Chrome extension both work standalone for auditing, converting, and applying fixes. The MCP server is only required for Supercharge - connecting Claude to drive both clients with natural language. See the Install Guide for setup order.

What happens if I disagree with a suggested fix?

Every fix is opt-in and reversible. You can snooze an individual flagged item, skip it entirely, or apply it and then revert - both clients keep a full edit history with undo/redo per step, including restoring prior variable bindings.

Does NiCE Designer work on any Figma file, or only CXone product files?

It works on any Figma file, but its audit rules are built against the SOL and Lyra foundation files, so compliance scoring is most meaningful on CXone product work. Running it against a file outside those systems will still surface off-token colors, spacing, and type, but there won't be a matching token to suggest as a fix.
