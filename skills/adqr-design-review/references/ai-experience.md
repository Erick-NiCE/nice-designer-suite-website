# AI Experience

Generated by `npm run gen:adqr-refs` from the rubric `score_design_review` reads. Never hand-edit. Rubric by Prafull Mane (ADQR).

Only when AI is present. A dimension whose concern genuinely does not apply is `outOfScope`, never a low band. Modality caps are applied by the tool, not by you: score what you see.

10 dimensions. Score each with exactly one band: 0, 2, 4, 6, 8 or 10.

## Intent First `intent_first`

**Does the experience focus on user goals rather than interface navigation?**

| Band | Anchor |
| --- | --- |
| 0 | Interface requires the user to manually navigate menus/screens to construct their own outcome; no goal-oriented entry point exists. |
| 2 | A goal-oriented entry point exists but is cosmetic — it still routes the user through the same manual multi-step navigation. |
| 4 | User can state a goal in one place, but the system only partially acts on it, requiring significant manual follow-up. |
| 6 | User states a goal and the system produces a relevant result, but with generic framing not tailored to their specific context. |
| 8 | User states a goal and receives a contextually tailored result requiring minimal manual adjustment. |
| 10 | The entire flow is organized around the user's stated intent end-to-end, with no manual navigation required to reach the outcome. |

## Human Control `human_control`

**Can users guide, modify, or override AI behavior?**

| Band | Anchor |
| --- | --- |
| 0 | No visible or working mechanism for the user to review, edit, or override AI output before or after it takes effect. |
| 2 | An override mechanism exists but is undiscoverable or requires exiting the primary flow entirely. |
| 4 | Override exists and is reachable, but only after the AI action has already applied (undo-only, no pre-commit review). |
| 6 | User can review AI output before it applies, but can only accept or reject — not modify. |
| 8 | User can review and directly edit AI output in-context before it applies. |
| 10 | User can review, edit, and set standing preferences that shape future AI behavior in this flow. |

## Transparency `transparency`

**Is it clear where AI is involved?**

| Band | Anchor |
| --- | --- |
| 0 | No indication anywhere that AI produced or influenced this output; it reads as fully manual/deterministic. |
| 2 | AI involvement is mentioned once, generically, disconnected from the specific output it produced. |
| 4 | AI-generated elements are labeled, but the labeling is inconsistent across the flow. |
| 6 | AI-generated elements are consistently labeled at the point of output. |
| 8 | Labeling additionally indicates the type of AI action taken (e.g., "AI drafted this reply"). |
| 10 | Labeling is consistent, specific, and links to a way to see what informed the AI's output. |

## Trust & Accuracy `trust_accuracy`

**Does the experience communicate confidence appropriately?**

| Band | Anchor |
| --- | --- |
| 0 | AI output is presented with the same certainty as verified data, with no confidence signal at all. |
| 2 | A confidence signal exists but is generic/decorative (e.g., a static disclaimer with no variation). |
| 4 | Confidence signal varies but isn't tied to anything the user can act on. |
| 6 | Confidence signal varies meaningfully and prompts caution on low-confidence outputs. |
| 8 | Confidence signal is specific enough to guide the user's next action (e.g., "verify before sending"). |
| 10 | Confidence signal is granular, tied to specific claims within the output, not just the output as a whole. |

## Explainability `explainability`

**Can users understand why AI produced its result?**

| Band | Anchor |
| --- | --- |
| 0 | No path exists to see why the AI produced this specific result. |
| 2 | A generic "how this works" link exists, disconnected from the specific result shown. |
| 4 | Explanation is available but requires leaving the flow to a separate help page. |
| 6 | In-context explanation is available on request, in general terms. |
| 8 | In-context explanation references the specific inputs that shaped this specific result. |
| 10 | Explanation is available by default (not click-to-reveal) and specific to the result shown. |

## Context Awareness `context_awareness`

| Band | Anchor |
| --- | --- |

| Band | Anchor |
| --- | --- |
| 0 | Automation level is fixed; no path shown for the user to take on more or less AI assistance over time. |
| 2 | A settings toggle exists for automation level but is disconnected from actual usage patterns. |
| 4 | System suggests increased automation, but acting on the suggestion still requires manual reconfiguration. |

## Efficiency `efficiency`

**Does AI meaningfully reduce user effort?**

| Band | Anchor |
| --- | --- |
| 0 | Completing the task with AI assistance takes the same or more steps than without it. |
| 2 | AI removes one minor step but the overall task length is essentially unchanged. |
| 4 | AI reduces effort for part of the task but the user must redo comparable manual work elsewhere in the flow. |
| 6 | AI measurably reduces the number of steps or fields the user must complete. |
| 8 | AI reduces effort across most of the task, leaving only final review/approval to the user. |
| 10 | AI reduces the task to a single review-and-confirm action from what was previously a multi-step manual process. |
