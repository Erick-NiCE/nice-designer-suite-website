# Requirement Coverage

Generated by `npm run gen:adqr-refs` from the rubric `score_design_review` reads. Never hand-edit. Rubric by Prafull Mane (ADQR).

Does the design implement what the requirement states, and can the user reach their goal? Split the requirement into parts first (see SKILL.md).

6 dimensions. Score each with exactly one band: 0, 2, 4, 6, 8 or 10.

## Requirement Coverage `requirement_coverage`

**How completely does the design represent the stated requirements?**

Excluded by the tool unless it needs the Requirement field.

| Band | Anchor |
| --- | --- |
| 0 | None of the stated requirement has any UI evidence. |
| 2 | Only a small fragment of the requirement has UI evidence. |
| 4 | Roughly half the stated requirement has clear UI evidence; the rest is unaddressed. |
| 6 | Most of the requirement is represented, with one clear, specific gap remaining. |
| 8 | The requirement is fully represented, with only minor ambiguity in one sub-part. |
| 10 | Every stated part of the requirement has clear, unambiguous UI evidence. |

Evaluate for:
- Is each requirement represented?
- Is its intended behavior represented?
- Is sufficient UI evidence available?
- Is the requirement only partially implemented?

Evidence to inspect: Requirement list; UI evidence; Screens; Prototype flow.

Do **not** evaluate:
- Whether the requirement itself is good
- Requirements not provided by PM

## Functional Completeness `functional_completeness`

**Does the UI provide all capabilities required to perform the requested function?**

Excluded by the tool unless it needs the Requirement field.

| Band | Anchor |
| --- | --- |
| 0 | None of the required actions, inputs, or controls needed to perform the function exist. |
| 2 | Only one of several required capabilities is present. |
| 4 | Roughly half the required capabilities are present; specific ones are identifiably missing. |
| 6 | Most required capabilities are present, with one specific one missing or incomplete. |
| 8 | All required capabilities are present, with only a minor completeness gap. |
| 10 | Every required action, input, output, and state described in the requirement is present. |

Evaluate for:
- Required actions
- Required inputs
- Required outputs
- Required controls
- Required states
- Required configuration options
- Required completion actions

Evidence to inspect: Requirements; UI controls; Screens; Flow states.

Do **not** evaluate:
- Backend implementation
- API correctness
- Performance

## Flow Completeness `flow_completeness`

**Does the submitted journey contain the required steps and states needed to complete the requirement?**

Excluded by the tool unless it needs the Requirement field, and needs 2 or more screens.

| Band | Anchor |
| --- | --- |
| 0 | The submitted screens skip directly from entry to an end state, with none of the required intermediate steps. |
| 2 | Only the entry and one other required state are shown; most of the required journey is missing. |
| 4 | Roughly half the required states (entry, configuration, review, success, error) are shown. |
| 6 | Most required states are shown, with one specific one (commonly the error/exception path) missing. |
| 8 | Nearly every required state is shown, with only a minor omission. |
| 10 | Entry, prerequisites, intermediate states, review, success, and error/exception paths are all shown. |

Evaluate for:
- Entry state
- Prerequisite steps
- Configuration steps
- Intermediate states
- Review/confirmation
- Success state
- Error/exception paths
- Exit/completion

Evidence to inspect: Multiple screens; Prototype flow; Navigation; State transitions.

Do **not** evaluate:
- Whether steps are in the best order — that is UX Flow
- Label clarity
- Visual quality

## Requirement Conflicts `requirement_conflicts`

**Does any part of the design contradict the stated requirements?**

Excluded by the tool unless it needs the Requirement field.

| Band | Anchor |
| --- | --- |
| 0 | A shown screen or control directly does the opposite of what a stated requirement requires. |
| 2 | A specific, clearly identifiable contradiction exists between two screens, or between a screen and the requirement. |
| 4 | A partial or ambiguous conflict exists — a screen could be read as contradicting the requirement, but it isn't certain. |
| 6 | No direct contradiction found, but one screen's behavior isn't explicitly confirmed as compliant. |
| 8 | No contradiction found across the screens that were checkable. |
| 10 | Every checked screen is explicitly and unambiguously consistent with the requirement, with no room for a conflicting reading. |

Evaluate for:
- UI contradicts an explicit requirement
- Screens contradict each other
- Interaction prevents required behavior
- AI introduces conflicting behavior
- One state violates another requirement

Evidence to inspect: Requirement; UI evidence; Conflict relationship.

Do **not** evaluate:
- Personal UX preferences
- Conflicts with undocumented assumptions

## User Goal `user_goal`

**Can the user accomplish their intended goal through the proposed experience?**

Excluded by the tool unless it needs the User Goal field.

| Band | Anchor |
| --- | --- |
| 0 | No path to the stated goal exists in what's shown; the primary action is missing or unrelated to the goal. |
| 2 | A path exists but is buried, mislabeled, or requires steps clearly outside what's shown to reach. |
| 4 | The path exists and is reachable, but at least one step or piece of information needed to complete it is missing or unclear. |
| 6 | The goal is reachable through a clear primary action, with only minor ambiguity about the exact end state. |
| 8 | The goal is clearly reachable via an obvious primary action, and the completion state is shown or implied. |
| 10 | The goal is reachable in the fewest reasonable steps, with the primary action, path, and completion state all unambiguous. |

Evaluate for:
- Is the user goal clear?
- Is the primary task supported?
- Is the primary action identifiable?
- Can the user reach the intended outcome?
- Does anything prevent completion?

Evidence to inspect: Persona; User goal; UI; Primary CTA; Completion state.

Do **not** evaluate:
- Whether the persona is correct
- Business goal
- Visual aesthetics
