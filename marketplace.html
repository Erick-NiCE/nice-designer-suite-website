What it is

Community capability, shipped alongside the core suite

The Marketplace is where skills the core team hasn't built end up. It's the front tab in the Supercharge panel whenever it has anything in it, and its entries load into Claude exactly like the built-in ones.

A Marketplace entry is a normal Claude skill - a SKILL.md file that gives Claude a playbook for one specific job. The only difference is who wrote it. Nothing is sandboxed differently and nothing needs a separate install; once an entry is accepted it ships with the suite and every connected Claude session picks it up.

Marketplace skills require Supercharge to be connected, same as every other skill. Run one by naming it in Claude chat - "run the ux-eval skill", or just "run North Star Fox".

⚠️
Marketplace entries are authored independently and aren't reviewed to the same depth as core skills. Check a card's byline before you rely on its output - especially for anything you're taking to a stakeholder.

Contributing

How to submit a skill

If you've built something useful enough that you'd want a teammate to have it, submit it. The process is deliberately light - write the skill, test it, send it over.

1
Write the SKILL.md

A skill is one folder with a single SKILL.md at its root. The folder name is the skill's id - lowercase, hyphenated, no spaces.

The file opens with YAML frontmatter, then the playbook in Markdown below it:

skills/my-skill-name/SKILL.md

---
name: my-skill-name
description: What the skill does, and when Claude should reach
  for it. Include the phrases a user would actually say.
disable-model-invocation: false
---

# My Skill Name

The playbook: what to do, in what order, which MCP tools to
call, what the output should look like, and what to watch for.
2
Make the description earn its trigger

The description field is the only thing Claude sees when deciding whether to load your skill. It does double duty: what the skill does, and when to invoke it.

Write out the phrases someone would really type - "run a UX eval", "is this ready for dev", "pass/fail this design". Vague descriptions are the single most common reason a skill never fires.

3
Keep the playbook specific

Skills earn their keep by removing guesswork. The strongest ones spell out:

  • Which MCP tools to call, and in what order
  • Which client the skill targets - Figma, Chrome, or both (call list_targets first)
  • The exact shape of the output, so results are comparable run to run
  • Failure modes and pitfalls worth calling out up front

Long reference material belongs in sibling files - a references/ folder next to SKILL.md - so the main playbook stays readable.

4
Test it end to end

With Supercharge connected, drop the folder into your local skills/ directory and run it by name in Claude chat - "run the my-skill-name skill". Claude finds it with list_skills and loads it with get_skill.

Run it against a real file or page, not a toy example. Then run it a second time on something different and check the output still holds its shape.

5
Send it to Erick

Message Erick Mathews on Teams with the skill folder and a sentence on the problem it solves. There's no PR process and no form to fill in.

Once accepted, it's added to the suite's skills/ directory and registered in the catalog under your name, flagged as a third-party entry. From there it appears in the Supercharge Marketplace tab, on this page, and in the Claude Skills reference - and ships to every connected session with no reinstall.
